# 经典数字游戏的体感重构：从“贪吃蛇”到“AI切水果”

本项目是一套基于 MediaPipe 和 OpenCV 的纯视觉体感交互系统。旨在打破传统游戏必须依赖鼠标、键盘或触屏的“屏幕禁锢”，用 AI 技术赋予经典游戏倡导健康、释放情绪的新属性。

项目分为两个演进阶段：**初代《AI体感贪吃蛇》** 与 **完全进化版《AI切水果》**。

---

## 🐍 阶段一：初代《AI体感贪吃蛇》 (Version 1.0)

回溯功能机时代，《贪吃蛇》是无数人的数字启蒙，但玩家只能僵硬地按压物理按键；到了智能手机时代，玩家依然被死死禁锢在几英寸的屏幕前。为了解决“低头族”的痛点，我们开发了初代作品：

通过电脑摄像头，玩家可以直接在空中挥动食指，引导屏幕中的蛇去吃甜甜圈。
![贪吃蛇开始](assets/photo/贪吃蛇开始.png)

- **玩法说明**：系统会实时捕捉你的指尖坐标，蛇头会紧紧跟随你的手指移动。吃到甜甜圈后蛇身变长、得分增加。
- **闯关与结算**：游戏包含关卡机制，过关或失败后会进入结算画面。按 `r` 键可以重新开始，按 `q` 键退出。
![贪吃蛇结算](assets/photo/结算画面.png)

**初代的局限与思考**：
在实际测试中我们发现，贪吃蛇的“方向引导”动作相对舒缓，仍不足以达到充分舒展上肢、释放情绪的锻炼效果。这启发我们挑战一个需要“高速挥砍”的交互场景——《切水果》。

## 🍉 阶段二：完全进化版《AI切水果》 (Version 2.0)

在初代贪吃蛇的视觉框架基础上，我们针对**高速动作捕捉、多线程渲染、复杂物理碰撞（防穿模）以及多手追踪防串线**进行了彻头彻尾的底层算法重构，最终诞生了这款支持双人同屏 PK 的《Swift-Fruit-Slice AI 切水果》。

### 1. 首页模式选择
运行游戏后，首先进入模式选择界面：
![首页选择](assets/photo/首页选择.png)

- **视觉交互**：举起一只手，将食指悬停在想要的模式方块上，绿色进度条走满（约 3 秒）即可确认。
- **键盘快捷键**（备用）：
  - 按 `1`：选择 **单手模式**（一只手切水果）
  - 按 `2`：选择 **双手模式**（两只手同时切水果）
  - 按 `3`：选择 **双人 PK**（两人同屏对战，限时 30 秒）
  - 按 `Esc`：直接退出游戏

### 2. 选择刀光皮肤
![选择刀的皮肤](assets/photo/选择刀的皮肤.png)
- 同样支持食指悬停选择，或者使用键盘 `1`（经典冷冽刀光）、`2`（狂暴烈焰刀光）。按 `q` 可快速跳过。

### 3. 核心切水果玩法
挥动你的手臂，享受高速挥砍的快感！系统内置了点线碰撞数学模型，无论你挥得多快，都不会出现“刀光穿模”的判定失误。
- **连击系统**：连续切中水果不漏掉会增加连击数，触发全屏炫酷特效。
- **躲避炸弹**：
  - 💣 **黑色炸弹 (普通炸弹)**：切到会扣除 3 分。
    <br>![黑色炸弹](assets/zhadan/boom1.png)
  - ☠️ **红色炸弹 (致命炸弹)**：切到会直接 Game Over，结束当前对局！
    <br>![红色炸弹](assets/zhadan/boom2.png)

### 4. 结算界面与重新开始
当一局游戏结束后，系统会自动计算得分或判定双人 PK 的胜负。
![结算选择](assets/photo/结算选择.png)
- **防误触延迟**：为了防止挥砍动作误触按钮，游戏结束时会有 **2 秒的防误触延迟**，随后交互方块才会浮现。
- **重新开始**：悬停食指在“重新开始”或“主菜单”方块上确认。也支持按 `r`（重开）或 `m`（主菜单）。

## 🛠️ 目录结构与运行指南

### 核心目录
- `main1.py`: 进化版《AI切水果》主程序入口（多线程采集 + 识别 + 渲染）。
- `vision_engine.py`: MediaPipe 手势识别封装（懒加载，支持 GPU/CPU 自动回退）。
- `config.py` & `settings.yaml`: 切水果游戏的热插拔配置与资源加载模块。
- `game_core.py`: 切水果核心逻辑与实体定义 (水果、炸弹、点线碰撞引擎)。
- `ui_screens.py`: 纯视觉控制的悬停 UI 界面组件。
- `logger.py` / `version.py`: 日志（logs/game.log）与版本号。
- `assets/` & `models/`: 游戏图像、音效素材及 MediaPipe AI 模型目录。

### 环境要求与安装
确保已安装 Python 3.9+。
使用以下命令安装依赖：
```bash
pip install -r requirements.txt
```

### 运行游戏
```bash
python main1.py
```

### 配置文件 `settings.yaml` 怎么配

> 修改后保存，**重启游戏**生效。源码运行改项目根目录的 `settings.yaml`；打包版改 **`main1.exe` 同目录**下的 `settings.yaml`。

#### `camera` —— 摄像头

| 参数 | 默认 | 说明 |
|------|------|------|
| `index` | `1` | 摄像头编号：`0`=内置/默认摄像头；`1`、`2`、`3`…=第一个、第二个外接摄像头 |
| `width` / `height` | `1280` / `720` | 采集分辨率。调低（如 640×480）通常能提高帧率 |
| `fps` | `60` | 请求帧率。实际以驱动为准，启动日志会打印真实值 |
| `mirror` | `true` | 画面镜像。`true` 像照镜子，`false` 为原始方向 |

**摄像头编号怎么定（画面打不开 / 用错摄像头看这里）**：

- 常见对应：笔记本内置摄像头多为 `0`，外接 USB 摄像头多为 `1` 或 `2`
- 编号填错**不会卡死**：程序会自动扫描 `0~3` 找可用摄像头；全都失败会提示「未检测到可用的摄像头」并退出
- 实际使用的编号会写进 `logs/game.log`，例如：`摄像头打开成功 index=1 分辨率 1280x720 驱动标称 60FPS`
- 画面只有 10 FPS 左右，通常是选到了低帧率摄像头，把 `index` 换成支持 60FPS 的那个即可

#### `game` —— 玩法与窗口

| 参数 | 默认 | 说明 |
|------|------|------|
| `window_width` / `window_height` | `1280` / `720` | 游戏窗口尺寸，改小可降低显卡/CPU 压力 |
| `spawn_interval` | `12` | 水果初始生成间隔（帧）。越小出得越快越密 |
| `min_spawn_interval` | `4` | 难度提升后允许的最小生成间隔（帧） |
| `max_on_screen` | `12` | 初始屏幕上最多同时存在的物体数 |
| `max_on_screen_cap` | `25` | 难度提升后物体数上限 |
| `difficulty_step_time` | `10` | 每隔多少秒提升一档难度 |
| `total_time` | `30` | 双人 PK 模式总时长（秒） |
| `fruit_theme` | `"default"` | 水果主题：`default`=普通水果；`ads`=广告图标（需配合 `ads` 段） |

#### `ai` —— 手势识别

| 参数 | 默认 | 说明 |
|------|------|------|
| `max_hands` | `6` | 最多同时识别的手数量。越低越省性能 |
| `delegate` | `"auto"` | 推理设备：`auto`=优先 GPU、失败自动退回 CPU；`cpu`=强制 CPU |
| `infer_width` / `infer_height` | `320` / `240` | 推理输入分辨率。调小更快、调大略准 |

#### `paths` —— 资源路径

| 参数 | 默认 | 说明 |
|------|------|------|
| `assets_dir` | `"assets"` | 素材根目录（相对 exe 所在目录） |
| `models_dir` | `"models"` | 模型根目录 |
| `model_name` | `"hand_landmarker.task"` | 手势识别模型文件名 |
| `bgm_name` | `"1.mp3"` | 背景音乐文件名 |

#### `ads` —— 广告主题（可选）

只有把 `game.fruit_theme` 改成 `"ads"` 时才会用到：

| 参数 | 默认 | 说明 |
|------|------|------|
| `scale` | `0.49` | 所有广告图标的统一缩放比例 |
| `custom_scales` | — | 单独微调某张图，例如 `shouji: 0.23`；未列出的仍用 `scale` |
